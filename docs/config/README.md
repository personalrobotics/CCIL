# Configuration

This is the configuration contract of the `ccil` core (#4). It is implemented in
[`src/ccil/config/`](../../src/ccil/config/).

- [`parameters.md`](parameters.md) is the generated reference for every
  parameter: type, default, units, domain, stage, status, rationale, and the
  legacy keys it replaces.
- [`parameter-audit.md`](parameter-audit.md) is the generated audit of every
  behavior-affecting value in the legacy code and ledger, with its canonical key
  and status.

Both files are generated from `src/ccil/config/params.py`, the one canonical
source. Regenerate them, or check them for drift:

```bash
uv run ccil config docs  [--check]
uv run ccil config audit [--check]
```

## Precedence

Package defaults < recipe (`--recipe`, from `src/ccil/recipes/`) < user file
(`--config`) < `--set key=value` < Python `resolve(overrides=...)`.

`uv run ccil config show [--recipe R] [--config F] [--set k=v]` prints every
effective value together with its source.

## Validation

Everything is checked before any output is written or any model is built:

- **Unknown keys** fail, with a suggestion for the closest valid key.
- **Types and domains:**
  - booleans accept only `true` or `false`, which fixes the legacy `bool("false")` defect;
  - integers must be integers;
  - numbers must be finite and within their declared range;
  - choices must be one of the listed options.
- **Units:** a number may be written as `"<n> <unit>"`, but only with exactly
  the declared unit. Nothing is converted.
- **Cross-field rules,** such as declaring action bounds together and
  `noise_bc` requiring a noise scale.
- **No ambiguity:** a key repeated in one YAML mapping fails at any level, as
  does one key spelled both nested and dotted (`run: {seed: 1}` with
  `run.seed: 2`).
- **Data-dependent rules,** checked once the dataset is read and before any
  run is written: each action bound is either one value or exactly the
  dataset's action dimension.

## Files and migration

- **New files** declare `config_version: 2` and nest keys by stage.
- **Version 1 files** are read with the meaning they had. Version 2 (#125)
  changed one default, `transition_model.lipschitz_coordinates`, from `raw`
  to `model_normalized`. A version 0 or 1 file that does not set it resolves
  to `raw`, and the resolved configuration notes it. Converted legacy
  configurations (#23) are written as version 1.
- **A file without `config_version`** is read as a legacy `correct_il` YAML
  (version 0) and migrated. Renamed keys move to their canonical key. Keys that
  never affected behavior are dropped with a note. Keys that affected behavior
  but have no supported home yet fail with guidance; the label-filtering keys,
  for example, point to #22.
- **The Pendulum recipes** were generated by this migration from
  `config/pendulum_{cont,disc}.yml`. Replaying the legacy file gives exactly
  the recipe's values.

## `data prepare`

`uv run ccil data prepare --recipe pendulum_cont --set data.path=... --set run.output_dir=runs`
validates the dataset, splits it by episode, and writes a run directory
in the [standard layout](../runs.md): `data/dataset.npz`, `data/split.json`,
`config.json`, `metrics.json`, `logs/run.log` and a hashed `manifest.json`.

- **Run ID:** derived from the configuration and the source data, so identical
  inputs reproduce the same directory byte for byte.
- **Existing runs:** an existing run directory is refused, unless
  `run.overwrite=true` is set, in which case it is replaced atomically.

## Evidence

```bash
uv run python tools/m2_config/check.py --out <new-dir>
```

[`../fixtures/evidence/m2-config/report.json`](../fixtures/evidence/m2-config/report.json)
has 23 cases:

- **Provenance:** default and override runs, with per-value sources, run IDs,
  the seed and output hashes.
- **Replay:** byte-identical from another working directory.
- **Overwrite:** an existing run is refused, then replaced atomically.
- **Failures before output:** twelve misconfigurations and a corrupt dataset.
  These include duplicate YAML keys at three levels and wrong-dimension action
  bounds, each with no traceback. The public `TrajectoryDataset.validate`
  reports wrong-dimension bounds as a `SchemaError`.
- **Parsing:** typed values and units, and Python-interface precedence.
- **Migration:** the legacy config replays to the recipe's values; an
  unsupported key fails with guidance; an unknown config version is rejected.
- **No docs drift.**
